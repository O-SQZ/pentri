# 데이터와 실행 경계

이 문서는 구현된 통제와 한계를 설명한다. 전체 웹 취약점 탐지·운영 환경의 무해성을 보증하지 않는다.

## 요청 범위

프로젝트에 origin, networkPolicy, 정확한 경로 1~20개를 저장한다. 실행 시작 시 사용자가 이 목록을 승인한다. private는 loopback/RFC1918/ULA, public은 지정 origin의 공인 unicast까지 허용한다. 양쪽 모두 metadata/link-local/reserved 주소와 앱/Ollama 포트를 차단한다. 포트 차단은 원격 대상에도 보수적으로 적용한다.

각 요청 전에 DNS의 모든 응답을 검증하고 검사한 주소로 소켓을 연결한다. 첫 성공 응답의 주소 집합을 실행에 저장하며 후속 DNS 집합이 다르면 요청을 거부한다. 새 실행에서는 다시 해석하므로 변경된 대상을 사용자가 재검토해야 한다. TLS 인증서 검증을 비활성화하지 않는다. 사내 CA는 Node가 신뢰하도록 운영 환경에 구성한다.

GET만 사용하며 redirect·링크·외부 스크립트를 따라가지 않는다. 인증 헤더·쿠키·사용자 입력 페이로드를 보내지 않는다. 기본 요청 간격 500ms, 전체 요청 timeout 8초, 수신 본문 상한 256KiB, 동시 진단 1개다. GET도 logout 등 상태를 바꿀 수 있으므로 경로 선택은 의미를 아는 운영자의 책임이다. 앱이 URL 의미를 판정할 수는 없다.

## LLM

규칙 실행과 판단 상태는 모델 권한 밖이다. 입력은 규칙 ID·제목·설명·기본 조치안·근거 ID로 최소화한다. URL/본문/쿠키/수집 JSON을 보내지 않으며 도구를 제공하지 않는다. 최대 4개 관찰씩 순차 요청한다. 모델과 prompts를 자동 설치·변경하지 않는다.

로컬 literal Ollama endpoint만 사용하고 설치된 GGUF 모델의 tags/show 메타데이터를 검사한다. 알려진 cloud/remote 표시를 거부하고 출력 JSON 키·길이·관찰 ID·중복·confidence를 재검증한다. confidence는 보정된 확률이 아니다. 응답 길이 1MiB, 호출 제한 시간 120초, 취소를 지원한다. 오래 걸리거나 불완전한 출력은 실패로 기록되며 진단 증적은 보존된다.

응답에 들어 있는 명령·링크·문구는 실행되지 않는다. 하지만 잘못된 조치안이나 설득성 문구가 포함될 가능성은 남는다. 운영자는 AI 의견을 근거와 대조해야 한다. 동일 모델명이 호스트에서 교체되는 경우까지 모델 실행 digest를 원격 증명하지는 않는다.

Ollama의 cloud 비활성화와 OS egress 통제는 별도 운영 조건이다. 앱이 임의의 로컬 서버가 거짓 메타데이터를 내거나 외부 프록시 역할을 하지 않는지 증명할 수 없다. 신뢰하는 단일 사용자 호스트를 전제한다.

## 로컬 API

127.0.0.1 바인딩, 정확한 Host, Origin, 정규화한 API 경로의 Sec-Fetch-Site 검사, 시작 시 생성한 메모리 토큰을 사용한다. CORS 허용 헤더를 제공하지 않는다. 브라우저 페이지는 토큰을 URL/로컬 저장소에 넣지 않는다. CSP, frame 차단, textContent/HTML 이스케이프를 적용한다. 같은 사용자로 실행되는 악성 로컬 프로세스와 디스크 직접 접근은 이 인증의 방어 범위가 아니다.

## 증적과 판정

원문은 수신 후 메모리에서 분석하고 본문 16,000자 발췌 및 헤더를 마스킹해 저장한다. 잘 알려진 토큰·Cookie/Authorization·쿼리 값·이메일 등은 마스킹하지만 임의의 업무기밀과 모든 개인정보 제거를 보증하지 않는다. `sha256`은 받은 원문 바이트(잘리면 prefix), `storedSha256`은 저장한 헤더·발췌·관찰의 JSON 해시다. 원문 전체를 보관하지 않으므로 완전한 forensic 원본 재현용 저장소는 아니다.

`candidate/confirmed/dismissed/fixed`는 검토 상태이고, `not_observed/still_observed/inconclusive/not_checked`는 자동 재검사 상태다. 403/500/redirect/잘린 응답/미지원 응답을 정상 판정으로 바꾸지 않는다. 이전 fixed 항목이 다시 관찰되면 후보로 재개방한다. 로그에는 이전 검토가 남는다.

감사 해시 체인은 저장된 이벤트의 변경 흔적을 점검한다. 외부 서명/외부 보관 head가 없어 전체 DB 재작성 또는 뒤쪽 이벤트 삭제를 탐지할 수 없다. 규칙·AI·운영자 각각의 판단 주체를 분리해 기록한다. DB 암호화·자동 만료·사용자 계정·원격 증명은 후속 과제다.
