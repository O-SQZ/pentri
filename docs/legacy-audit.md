## 1. 결론과 요구 우선순위

현재 패키지는 브라우저 페이지의 단서를 수집하고 수동으로 경로·소스맵을 확인하는 MV3 확장 프로그램이다. 팝업 중심 상태 관리와 네트워크 실행을 그대로 확대하면 대상 혼합, 중단 후 결과 혼입, 민감정보 저장 및 LLM 입력 경계 문제가 함께 커진다. **독립 로컬 앱에 작업·정책·증적·보고서를 두고 확장은 명시적으로 선택한 페이지의 수집기로 재구성**하는 방향을 권고한다.

현재 사용자 요청이 [기존 v1.20 요구사항](pentri-v1.20-requirements.md)보다 우선한다. 기존 문서의 “별도 exe는 장기 후보”와 “스토어 업데이트”는 이번 작업의 필수 선행 조건으로 적용하지 않는다. 우선 순위는 내부망에서 사용할 Ollama 기반 독립 실행, 안전한 자동화와 검증, 저장소 정리다. 상용 LLM 연결과 스토어 배포는 이후 선택적으로 다룬다. 완전 자동화는 장기 목표이며, 이 ZIP 또는 첫 구현이 이를 달성했다고 간주하지 않는다.

## 4. 재사용할 관찰과 새로 설계할 영역

### 재사용 가능한 개념

- 입력 필드·폼·업로드의 메타데이터. 값과 비밀번호 수집은 기본에서 제외한다.
- DOM 주석, JS 리소스 URL, 보안 헤더 및 소스맵의 **관찰 사실**. 각각 출처·수집 시각·제한·증적 ID를 보강한다.
- 후보 / 접근 제한 / 확인 실패를 나누는 소스맵 상태 모델. 잘린 JSON은 “없음”이 아니라 “불완전한 관찰”로 기록한다.
- 정적 JS 규칙의 의도. 위험 함수 존재와 입력 흐름·실제 취약성은 구별한다.
- 자주 사용하는 진단 문구의 생성·편집·복사 흐름. 메시지 자동 전송 요구로 확대하지 않는다.

### 새로 설계할 영역

1. **로컬 실행 코어:** 프로젝트, 대상, 허용 범위, run, 작업 상태, 요청 예산, 취소, 재시도, 결과 저장을 UI 수명에서 분리한다. 네트워크 요청은 검증된 작업 종류만 제공한다.
2. **독립 앱:** 브라우저에서 로컬 UI를 별도 탭으로 열고 같은 코어의 CLI를 제공하면 확장 설치 없이도 파일 기반 관찰 분석·보고서를 사용할 수 있다. exe 등 네이티브 패키지는 검증 이후 결정한다.
3. **확장 수집기:** 사용자 선택 시 현재 탭의 허용된 DOM 관찰을 수집한다. 전송되는 데이터에 schema version·정확한 URL·수집 시각을 넣고 전체 페이지 지시문을 실행 지시로 취급하지 않는다. 첫 단계의 파일 내보내기/가져오기는 로컬 API 직접 연결보다 인증 경계가 단순하다.
4. **LLM 어댑터:** Ollama에는 마스킹된 관찰을 전달한다. 모델 출력은 스키마와 증적 참조를 검증해 검토 제안으로 저장한다. 모델에 shell·임의 HTTP·자격증명·설정 수정 권한을 제공하지 않는다. 네트워크 동작은 프로그램이 검증한 scope와 작업 정책으로 결정한다.
5. **증적과 판단:** observation, finding, evidence, model suggestion, reviewer decision을 연결하되 구별한다. 진단 ID, 원본 해시, 수집 시각, 규칙/모델 버전, 변경 이력을 남긴다. 재점검은 이전 실행을 덮어쓰지 않고 비교한다.
6. **완전 자동화 검증:** 진단 범주별 오탐/미탐 기준과 중단 조건을 정의하고 로컬 fixture에서 입증한 작업부터 자동화 범위를 늘린다. LLM 답변 또는 CVE 키워드 일치만으로 “취약 확정/조치 완료”를 만들지 않는다.

이는 이관 권고이며 전 항목 구현 완료를 뜻하지 않는다. 실제 첫 구현 및 검증 범위는 저장소의 현재 설계·테스트 문서와 대조한다.

[Acorn 공식 LICENSE](https://github.com/acornjs/acorn/blob/master/acorn/LICENSE)는 MIT 고지와 허가문 보존 조건을 명시한다. 확인한 웹 페이지는 현재 master이며 첨부 8.11.3의 배포물 대조를 대신하지 않는다. [Wappalyzer 현재 서비스 약관](https://www.wappalyzer.com/terms/)도 상용 서비스 데이터에 별도 조건을 두지만, 이 사실만으로 출처 불명인 첨부 DB의 과거 라이선스를 판단할 수는 없다. 원본 DB의 취득 근거 확인이 필요하다.

라이선스 미확인은 자체 코어·새 수집기·fixture 개발을 막는 사유가 아니다. 출처 불명 자산을 복사하지 않는 방식으로 진행할 수 있다.

## 7. 검증 한계와 다음 확인

이번 분석은 ZIP 목록·코드·요구사항의 정적 대조다. 외부 대상 진단, ZIP 스크립트 실행, Chrome 설치, Ollama 모델 다운로드/추론, 스토어 제출은 수행하지 않았다. 코드에 있는 기능이 실제 환경에서 정상 실행된다는 보증도 아니다.

레거시 보존이 필요하면 원본 SHA-256과 이 문서를 기준으로 별도 격리 경로에서 브라우저 재현을 한다. 새 버전에서는 먼저 대상 범위 이탈, 유사 도메인, 리다이렉트, 응답 제한, 중단/재시작, 악의적 페이지 지시문, 잘못된 모델 JSON, 미확인 증적 ID, 보고서 escape, 마스킹, 재점검 이력을 fixture로 검증해야 한다. 실제 내부망 연결과 모델 성능 평가는 이 기반의 결과와 분리해 기록한다.
